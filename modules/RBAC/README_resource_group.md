# 🏷️ RBAC — Resource-group scope

Assigns an Azure role on an existing resource group. The template is subscription-scoped so it can target the requested resource group by name.

## Inputs

| Parameter | Description |
|---|---|
| `resourceGroupName` | Existing target resource group name |
| `principalId` | Existing Microsoft Entra object ID |
| `roleDefinitionGuid` | Role definition GUID |
| `principalType` | `User`, `Group`, or `ServicePrincipal` |

## Deployment

```powershell
az deployment sub what-if --location EastUS --template-file modules/RBAC/RBAC_resource_group.bicep --parameters resourceGroupName="<RESOURCE_GROUP>" principalId="<OBJECT_ID>" roleDefinitionGuid="acdd72a7-3385-48ef-bd42-f606fba81ae7" principalType="User"
az deployment sub create --name "rbac-resource-group" --location EastUS --template-file modules/RBAC/RBAC_resource_group.bicep --parameters resourceGroupName="<RESOURCE_GROUP>" principalId="<OBJECT_ID>" roleDefinitionGuid="acdd72a7-3385-48ef-bd42-f606fba81ae7" principalType="User"
```

The example GUID is the built-in **Reader** role. In the workflow, the target resource group is selected from the resource group object in `input.json`; keep the RBAC target name aligned with the resource group generated by the ticket.

## Prerequisites

- The target resource group and principal must already exist when this deployment runs.
- The deploying identity must be allowed to create role assignments at the target scope.
- No managed group/identity creation is performed by this module. The requested principal must be provisioned separately.
- For least privilege, the sample input grants **Reader**. Change the role only when the ticket explicitly requests and approves a broader permission.

## Outputs

- `roleAssignmentId`
- `assignedResourceGroupId`
