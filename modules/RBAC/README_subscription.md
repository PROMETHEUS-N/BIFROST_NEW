# 🔐 RBAC — Subscription scope

Assigns an Azure role to an existing Microsoft Entra principal at the subscription scope. This template is available for direct use; the current GitHub Actions RBAC job does **not** yet consume subscription-scope entries from `input.json`.

## 1. Inputs

| Input | Type | Required | Example / allowed values | Purpose |
|---|---|---:|---|---|
| `principalId` | string | Yes | Entra object ID GUID | Identifies the existing user, group, or service principal receiving access |
| `roleDefinitionGuid` | string | Yes | Reader: `acdd72a7-3385-48ef-bd42-f606fba81ae7` | Selects the built-in or custom role definition |
| `principalType` | string | No | `User`, `Group`, `ServicePrincipal` (default: `User`) | Tells Azure the type of principal |
| `assignmentSeed` | string | No | Any stable string | Makes a distinct assignment name when the same principal/role combination needs a separate deterministic name |

### Input source and validation

- Inputs are passed as Bicep deployment parameters, either directly through Azure CLI or through an ARM parameters JSON file generated by an automation workflow.
- `principalId` must identify a principal that already exists in Microsoft Entra ID.
- `roleDefinitionGuid` must identify a role definition available at the subscription.
- Validate the role name and GUID together before deployment; do not trust an unreviewed ticket value.
- `assignmentSeed` is optional. Leave it empty for the default deterministic assignment name.

## 2. How the template generates the assignment

1. `subscriptionResourceId('Microsoft.Authorization/roleDefinitions', roleDefinitionGuid)` constructs the full role-definition resource ID in the current subscription.
2. `guid(subscription().id, principalId, roleDefinitionId)` creates a deterministic assignment name. If `assignmentSeed` is supplied, it is included in the GUID inputs.
3. The `Microsoft.Authorization/roleAssignments@2022-04-01` resource is deployed at subscription scope with the principal ID, principal type, and role-definition ID.

## 3. Outputs

| Output | Type | Generated from | Meaning |
|---|---|---|---|
| `roleAssignmentId` | string | `roleAssignment.id` | Full Azure resource ID of the created role assignment |

The template does not output the principal's display name, role display name, or a deployment summary. Those can be collected separately with Azure CLI if required.

## 4. What is created

- One `Microsoft.Authorization/roleAssignments` resource at subscription scope.
- The assignment name is generated deterministically by the `guid()` function.
- The principal and role definition are referenced; they are not created by this template.

## 5. Deployment example

Run from an authenticated Azure CLI session with `Microsoft.Authorization/roleAssignments/write` permission:

```powershell
az deployment sub what-if --location EastUS --template-file modules/RBAC/RBAC_subscription.bicep --parameters principalId="<OBJECT_ID>" roleDefinitionGuid="acdd72a7-3385-48ef-bd42-f606fba81ae7" principalType="User"

az deployment sub create --name "rbac-subscription" --location EastUS --template-file modules/RBAC/RBAC_subscription.bicep --parameters principalId="<OBJECT_ID>" roleDefinitionGuid="acdd72a7-3385-48ef-bd42-f606fba81ae7" principalType="User"
```

The example GUID is the built-in **Reader** role. Use a different role GUID only when approved.

## 6. Prerequisites and limitations

- The principal must already exist in Microsoft Entra ID.
- The deploying identity must be authorized to create role assignments at subscription scope (commonly User Access Administrator or Owner, subject to Azure role-assignment conditions).
- This module does not create users, groups, or managed identities.
- This template is not currently wired to the repository's `input.json` / `deploy.yml` RBAC loop. The current automated path handles resource-group assignments only.

## 7. Expected deployment result

A successful deployment creates or confirms the role assignment and exposes `roleAssignmentId` as a Bicep deployment output. Review the What-If result before applying the assignment.
